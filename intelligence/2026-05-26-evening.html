🧪 QA-Lab全面升级：Codex-vs-Pi Runtime Parity成为发布硬门槛

来源：releasebot.io / GitHub · 2026-05-17 | 阅读原文

OpenClaw最新发布将QA-Lab Runtime Parity Gates从可选测试升级为发布阻塞门槛，确保Codex-native工具与OpenClaw动态工具在行为上完全一致。关键升级包括：

  • Runtime Parity Tier：新增 --runtime-parity-tier 参数，将标准Codex-vs-Pi测试层与可选/仅在线/浸泡测试通道分离，实现分层质量管控
  • 工具覆盖率报告：新增 openclaw qa coverage --tools 命令，可查看Codex-native、OpenClaw动态和插件工具的覆盖率对比，缺失必需工具练习将直接失败
  • Token效率追踪：在all-lanes QA工作流中增加实时前沿Codex-vs-Pi运行时token效率制品通道，区分Codex节省与回退
  • 个人Agent场景扩展：新增审批拒绝场景（验证被拒绝的本地读取是否干净停止）、本地任务跟进场景（pending/blocked/done状态报告）、记忆晋升影子试验（不修改MEMORY.md即可评估候选记忆）
  • 100-turn浸泡测试：新增仅在线的Codex Pi-shaped Read词汇金丝雀，捕获原生workspace-read提示兼容性漂移

解读：OpenClaw正在从"功能竞赛"转向"一致性工程"——不再只比谁功能多，而是确保每个功能在Codex和Pi运行时中行为完全一致。对销售团队而言，这意味着部署OpenClaw时的跨模型兼容性风险将显著降低，企业级稳定性得到实质保障。

📱 Android Talk Mode升级：实时Gateway中继语音会话

来源：releasebot.io / GitHub · 2026-05-17 | 阅读原文

Android端的Talk Mode完成重大架构升级，从传统的"录制→上传→等待回复"模式切换为实时Gateway中继语音会话：

  • 流式麦克风输入：实时捕获用户语音流，无需等待录音完成
  • 实时音频播放：AI回复以流式音频方式实时播放，延迟显著降低
  • 工具结果桥接：语音会话中可直接触发工具调用（如"帮我查一下今天的日程"），工具结果通过语音反馈
  • 屏幕转录显示：实时显示语音转录文本，方便用户确认AI理解是否正确

解读：对销售团队而言，这意味着OpenClaw在移动端的可用性大幅提升——销售人员在通勤、拜访客户途中可以通过语音与AI助手交互，实时获取客户信息、更新CRM、发送跟进邮件。语音交互的流畅度从"能用"升级到"好用"，是移动端销售场景的关键基础设施。

🔒 Codex安全加固：图像消毒+线程绑定清理+嵌套结果扁平化

来源：releasebot.io / GitHub · 2026-05-17 | 阅读原文

Codex app-server获得多项关键安全与可靠性修复：

  • 图像载荷消毒：在Codex app-server和OpenAI Responses重放之前，对inline image payloads进行清理，防止恶意图像数据注入攻击，并在无效图像错误后清除被污染的Codex线程绑定
  • 嵌套工具结果扁平化：将嵌套的工具结果中间件块展平为有限文本，修复"Tool output unavailable due to post-processing error"错误——此前成功的消息发送会被此错误替换
  • 媒体生成失败直传：当异步图像/音乐/视频生成完成且请求者会话交接失败时，直接将失败结果传递给通道用户——用户现在能看到提供商错误信息而非静默卡住
  • GitHub Copilot安全修复：在调度前丢弃带有不可重放ID的不安全原生Responses推理重放项，防止Copilot会话因invalid_request_body而失败

解读：这是OpenClaw从"炫技"到"可治理"的明确信号。安全修复不再是可选补丁，而是发版阻塞项。企业部署OpenClaw时，对图像处理和数据安全的合规要求将得到更好满足——对金融、医疗等强监管行业的销售团队尤其重要。

🔄 Subagent可靠性双修复：超时保活 + 完成结果保留

来源：releasebot.io / GitHub · 2026-05-17 | 阅读原文

Subagent（子代理）系统获得两项关键可靠性修复：

  • 超时保活：当子代理等待调用在子会话实际完成之前超时时，保持基于会话的父运行活跃——晚到的子代理完成现在会被核对而非丢失

📱 Telegram增强：隐私脱敏 + 群组回复链 + DM草稿预览

来源：releasebot.io / GitHub · 2026-05-17 | 阅读原文

Telegram通道获得隐私、正确性和用户体验三重提升：

  • 元数据脱敏：在verbose原始更新日志中对嵌套原始更新标识符和用户元数据进行脱敏——保留有用的更新/消息ID，但不暴露聊天、用户、命令或个人资料详情，满足GDPR/个保法要求
  • 群组回复链：保留群组回复链中被回复的机器人消息、标题和媒体元数据——后续回复现在能理解用户在回应什么
  • DM草稿预览：允许列入白名单的原生DM草稿预览用于瞬态工具进度，最终答案仍走正常持久化交付路径
  • 孤立处理修复：将停滞的孤立入口处理程序转入墓碑状态，并在重启前中止同通道回复工作——后续同聊天更新在挂起轮次后能够正常排空

解读：隐私脱敏是企业合规部署的硬门槛。OpenClaw在日志中自动处理PII（个人身份信息），意味着销售团队通过Telegram通道触达客户时，无需额外配置即可满足GDPR/个保法要求。这对跨国企业和出海业务的销售团队尤为重要。

🔧 Gateway与CLI多项可靠性修复

来源：releasebot.io / GitHub · 2026-05-17 | 阅读原文

Gateway基础设施和CLI工具链获得多项生产级修复：

  • Gateway会话轮换：当代理会话的转录文件缺失时轮换失败的代理会话，而不是卡住每通道队列——修复#83488
  • Gateway更新检查：将更新检查启动推迟到就绪之后，使包更新检查不再阻塞sidecar就绪启动，同时保留更新广播和关闭清理
  • Gateway重启排水：在重启关闭期间排空待处理回复和活跃聊天轮次，中止超时聊天轮次——修复#69121

  • CLI/doctor：在迁移旧版非loopback网关绑定主机别名（如0.0.0.0）时，为Control UI播种允许的来源
  • CLI/update：根据平台定制更新后Gateway恢复提示，显示systemd、LaunchAgent、Scheduled Task或通用服务管理器指导
