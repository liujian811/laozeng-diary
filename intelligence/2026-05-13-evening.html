🎯 OpenClaw最新动态

OpenClaw 2026.5.9-beta.1：失败自愈导航与生产级安全加固

来源：OpenClaw GitHub Releases / 2026-05-11

2026.5.9-beta.1的核心主题是"让失败变得可解释、可恢复"——当Agent或CLI出问题时，系统不再抛出晦涩错误，而是直接告诉你"发生了什么"和"下一步该运行什么命令"：

  • CLI失败自愈导航：parser、startup、config、guardrail、channel、agent、task、session、MCP等各类失败场景，都会输出解释性错误信息并指向恢复命令。这意味着运营团队不再需要翻文档猜错误含义——系统直接教你怎么修复。
  • GitHub Copilot动态模型目录：从${baseUrl}/models实时刷新模型目录，包含最新gpt-5.5等模型；静态清单作为降级方案。Copilot用户现在可以第一时间用上OpenAI最新模型，无需等待静态配置更新。
  • Active Memory插件工具授权：支持plugins.entries.active-memory.config.toolsAllow自定义记忆插件召回工具名，同时保留内置memory-core默认行为。企业可以精确控制"哪些记忆工具可以被哪些插件使用"，实现细粒度的记忆访问控制。
  • Telegram/Feishu推理预览优化：根据per-agent和全局reasoningDefault值决定是否显示推理流预览，解决预览默认行为不一致问题。对于使用飞书/Telegram的企业客户，推理过程现在更符合预期——不会突然暴露或隐藏思考链。
  • Docker tini进程管理：runtime镜像默认使用tini作为init系统，正确回收孤儿进程并转发信号。长期运行的Docker容器不再因僵尸进程累积而变慢或崩溃。
  • 日志密钥脱敏：共享日志和格式化错误输出中，自动脱敏HTTP客户端secret字段和auth/cookie头。生产环境的日志现在可以安全地分享给支持团队或写入外部SIEM，不用担心密钥泄露。
  • 任务账本RPC稳定化：tasks.list、tasks.get、tasks.cancel的RPC接口文档化并稳定化，包含Swift模型类型。第三方客户端和移动端可以可靠地查询和管理后台Agent任务。
  • Google Gemini别名规范化扩展：退役的google/gemini-3-pro-preview和嵌套代理目录ID在配置加载和写入期间自动映射到google/gemini-3.1-pro-preview。用户不需要手动迁移配置——系统自动处理。
💡 销售业务价值：2026.5.9-beta.1的改进是"企业级可信度"的继续强化：①CLI自愈导航=降低技术支持成本。客户部署OpenClaw时如果遇到配置问题，错误信息本身就包含解决方案，减少了对文档和人工支持的依赖。②Copilot动态目录=销售团队永远能用最新模型做演示，不需要说"等新版本支持"。③Active Memory工具授权=企业可以隔离敏感记忆（如客户数据）和通用记忆，满足合规要求。④日志脱敏=满足SOC 2、等保等审计要求——"我们的日志不含密钥"。⑤Docker tini=长期运行的销售Agent（如24/7客服）不会因为进程泄漏而崩溃。⑥任务账本RPC=企业可以开发自定义仪表盘监控所有Agent任务状态，集成到现有运维体系。

OpenClaw 2026.5.10-beta.5：上下文可视化、本地模型启动、Slack精细化控制

来源：OpenClaw GitHub Releases / 2026-05-13

2026.5.10-beta.5在开发体验、模型基础设施和频道控制方面推出多项实用改进：

  • /context map 上下文可视化：新增/context map命令，发送当前会话上下文贡献者的treemap（树状图）。运营人员可以一眼看出"是什么占用了我的token"——是历史消息？是文件？是技能？是记忆？诊断token消耗的直观工具。
  • localService 本地模型按需启动：provider级别的localService启动，在OpenAI兼容请求前按需启动本地模型服务器，包含一次性模型探针。使用Ollama等本地模型的用户不再需要手动启动服务——OpenClaw自动按需唤醒。
  • pnpm 11 全面升级：工作区包管理升级到pnpm 11，Docker、安装、更新和发布工作流全部对齐。更高效的依赖管理=更快的安装和更新。
  • Slack精细化控制：新增unfurlLinks和unfurlMedia配置，支持按账号覆盖Slack链接和媒体预览；新增replyBroadcast支持，Agent可以选择将线程回复广播到父频道。这意味着销售团队在Slack中使用OpenClaw时，可以控制消息预览行为，避免 clutter。
  • Codex工具所有权固化：Codex app-server现在始终拥有workspace、edit、patch、exec、process和plan工具，移除可配置的动态工具profile。这简化了Codex Agent的行为预期——它总是有完整的编码工具集。
  • Agent默认提示词精简：修剪默认系统提示词指导和send-only消息工具schema，减少提示token消耗，同时保留GPT-5个性指导。更长上下文窗口=更多历史保留=更好的对话连贯性。
  • 插件SDK弃用清理：弃用存在至少一个月且无生产导入的公共子路径，保留legacy barrel/test/zod导出。插件生态在向更干净、更聚焦的API表面演进。
💡 销售业务价值：这些改进直接提升日常使用体验：①/context map=当客户问"为什么我的Agent不响应了"时，可以运行/context map检查token消耗——可能是某个大文件或长记忆占用了空间。②localService=使用本地模型（如Llama、DeepSeek本地版）的企业客户不再需要手动管理模型服务器启动——"像云服务一样使用本地模型"。③pnpm 11=更快的安装=更短的POC时间。④Slack控制=销售团队在Slack频道使用Agent时，可以选择不展开链接预览（保持频道整洁），或选择广播线程回复（让所有人看到关键更新）。⑤Codex工具固化= predictable behavior。销售演示中Codex Agent的表现不会因为配置差异而不同。
