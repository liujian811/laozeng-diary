🧪 QA-Lab大规模升级：Runtime Parity Gates成为发布门槛

来源：releasebot.io / GitHub · 2026-05-25 | 阅读原文

OpenClaw今日将Runtime Parity Gates从可选测试升级为发布阻塞门槛——Codex-native工具与OpenClaw动态工具之间的行为一致性现在必须通过硬门禁才能发版。具体升级包括：

  • Runtime Parity Tier：新增 --runtime-parity-tier 参数，将标准Codex-vs-Pi测试层与可选/仅在线/浸泡测试通道分离
  • 工具覆盖率报告：新增 openclaw qa coverage --tools 命令，可查看Codex-native、OpenClaw动态和插件工具的覆盖率对比
  • Token效率追踪：在all-lanes QA工作流中增加实时前沿Codex-vs-Pi运行时token效率制品通道
  • 个人Agent场景：新增审批拒绝场景（验证被拒绝的本地读取是否干净停止）、本地任务跟进场景（pending/blocked/done状态报告）、记忆晋升影子试验（不修改MEMORY.md即可评估候选记忆）

解读：这意味着OpenClaw正在从"功能竞赛"转向"一致性工程"——不再只比谁功能多，而是确保每个功能在Codex和Pi运行时中行为完全一致。对销售团队而言，这意味着部署OpenClaw时的跨模型兼容性风险将显著降低。

#QA-Lab #RuntimeParity #Codex #质量门禁

🔒 Codex安全加固：图像载荷消毒+线程绑定清理

来源：releasebot.io / GitHub · 2026-05-25 | 阅读原文

Codex app-server修复了关键安全问题：

  • 图像载荷消毒：在Codex app-server和OpenAI Responses重放之前，对inline image payloads进行清理，防止恶意图像数据注入攻击
  • 线程绑定清理：在无效图像错误后清除被污染的Codex线程绑定，防止错误状态传播到后续请求
  • 嵌套工具结果扁平化：将嵌套的工具结果中间件块展平为有限文本，修复"Tool output unavailable due to post-processing error"错误
  • 媒体生成失败直传：当异步图像/音乐/视频生成完成且请求者会话交接失败时，直接将失败结果传递给通道用户——用户现在能看到提供商错误信息而非静默卡住

解读：这是OpenClaw从"炫技"到"可治理"的又一标志。安全修复不再是可选补丁，而是发版阻塞项。企业部署OpenClaw时，对图像处理和数据安全的合规要求将得到更好满足。

#Codex #安全修复 #图像消毒 #线程绑定

🔄 Subagent可靠性双修复：超时保活+完成结果保留

来源：releasebot.io / GitHub · 2026-05-25 | 阅读原文

Subagent（子代理）系统获得两项关键可靠性修复：

  • 超时保活：当子代理等待调用在子会话实际完成之前超时时，保持基于会话的父运行活跃——晚到的子代理完成现在会被核对而非丢失
  • 完成结果保留：在最终交付重试耗尽后，保持keep-mode完成载荷处于pending状态——请求者恢复时不再丢失最终子代理结果

解读：Subagent是OpenClaw实现复杂多步骤工作流的核心机制（如"先搜索线索→再分析需求→再起草邮件→再发送"）。这两项修复消除了子代理结果丢失的尾部风险——对需要可靠性的销售自动化流程是重大利好。

#Subagent #可靠性 #工作流 #会话管理

📱 Telegram隐私增强：元数据脱敏+群组回复链保留

来源：releasebot.io / GitHub · 2026-05-25 | 阅读原文

Telegram通道获得隐私和正确性双修复：

  • 元数据脱敏：在verbose原始更新日志中对嵌套原始更新标识符和用户元数据进行脱敏——保留有用的更新/消息ID，但不暴露聊天、用户、命令或个人资料详情
  • 群组回复链：保留群组回复链中被回复的机器人消息、标题和媒体元数据——后续回复现在能理解用户在回应什么
  • DM草稿预览（今日已覆盖）：允许列入白名单的原生DM草稿预览用于瞬态工具进度，最终答案仍走正常持久化交付路径

解读：隐私脱敏是企业合规部署的硬门槛。OpenClaw在日志中自动处理PII（个人身份信息），意味着销售团队通过Telegram通道触达客户时，无需额外配置即可满足GDPR/个保法要求。
